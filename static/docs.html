Getting started

Memory for your agents.

Store what matters. Find it when you need it. LightMem gives your AI tools persistent local memory through a native CLI, Python SDK, and MCP server.

v0.5.2Rust + SQLiteLocal by defaultMIT licensed
Quick startFrom installation to your first recall.→ Connect your agentSet up skills, MCP, and shared memory.→
01

Install and run

The Python package bundles or locates the native lmem executable. Shell installers prefer release binaries and fall back to Cargo.

Install LightMem

Python 3.8+
pip install -U lmem

Supported wheels include the native executable. No Python dependencies required.

macOS / Linux
curl -fsSL https://raw.githubusercontent.com/krishnakanthpathi/lightmem/main/install.sh | sh

The installer prefers a release binary and falls back to Cargo when needed.

Rust toolchain required
git clone https://github.com/krishnakanthpathi/lightmem.git
cd lightmem
cargo install --path . --force

Build the native CLI directly from the repository.

Your first memory cycle

First memory cycle
$ lmem remember "Auth service runs on port 8180" --title "Auth Port" --tags "auth,docker"
$ lmem remember "System architecture diagram" -f ./arch.png --tags "arch,diagram"
$ lmem recall "auth port" --limit 5
$ lmem recall "architecture diagram" --media image --path
$ lmem answer "Which port does auth use?" --json
$ lmem stats
First model use: Local models download when first needed. Run lmem config --download all in advance to prepare the default models for offline use.
Database selection: --db PATH wins, then LIGHTMEM_DB. Otherwise LightMem uses ~/.lightmem/memories.db with --global, an existing project .lightmem.db in the current/ancestor Git scope, then the global database.

03

Data model and storage

Memory cards are durable records with lifecycle metadata; full-text, vector, graph, and immutable binary attachment structures are stored beside them in SQLite schema version 5.

MemoryRecord

  • idUUID v4
  • categoryMemoryType
  • title / contentString
  • tagsJSON array
  • confidencef32 · 0…1
  • statusactive | expired
  • provenanceString
  • contextoptional source identity + session
  • attachmentsVec<AttachmentMetadata>
  • created / updated / expiresUTC timestamps

SQLite v5

  • memoriescanonical records
  • memory_attachmentsimmutable BLOBs + SHA-256
  • memories_ftsFTS5 · porter unicode61
  • memory_vectorsLE f32 blobs + dims
  • embedding_stateidentity + dimensions
  • storage_revisionatomic reindex guard
  • memory_linksdirectional graph edges
  • memories.context_jsonoptional source metadata
  • journaling / permsWAL / 0600 owner-only

Fourteen memory categories

factdecisioninstructionpreferencelearninggoalcommitmentartifacteventrelationshipobservationerrorcontextpassword

Inference applies ordered heuristics: explicit prefixes, credentials, errors, decisions, imperatives, preferences, instructions, goals, commitments, learnings, events, relationships, observations, artifacts, then context; unmatched content becomes fact (or artifact when files are attached without explicit category).

Persistence & attachment semantics

  • FTS insert/update/delete triggers keep memories_fts synchronized (indexing title, content, tags, and attachment filenames/MIME/media types/dimensions/SHA-256).
  • memory_attachments stores binary payloads as SQLite BLOBs with a BEFORE UPDATE immutability trigger and ON DELETE CASCADE cleanup when a memory is forgotten with --hard.
  • Pure-Rust header parsers extract PNG, JPEG, GIF, and WebP dimensions; WAV, MP3, FLAC, and OGG audio durations; and MP4/MOV/WebM/MKV video dimensions and durations without external media libraries.
  • TTL values support ms, s, m, h, d, and w; due records are lazily expired during reads.
  • Exact deduplication keys combine category, normalized content, and sorted attachment SHA-256 digests.
  • IDs resolve by full UUID or unique prefix; inspection/link endpoints additionally resolve exact or unique substring titles.

04

Hybrid retrieval pipeline

Keyword and semantic channels are independently ranked, fused, lexically adjusted, hydrated, and deduplicated. The final score is a ranking signal—not a probability.

01 / QUERYNormalizeRemove common question words for FTS; retain raw query for vector embedding.
02 / BM25FTS5 prefixesQuoted prefix terms; 3–6 token misses retry OR token-pairs.
03 / VECTORCosine scanEmbed query, validate identity/dimensions, rank eligible stored vectors.
04 / FUSIONRRF k=60Each channel contributes 1 / (60 + rank).
05 / BOOSTLexical rescueInitials, exact tokens, tags, deduplication, category/date filters.
Final ranking
rrf = Σ 1 / (60 + rank_channel)
lexical_boost = min(0.35, initials + exact_token_or_tag)
final_score = 0.85 × normalized_rrf + 0.15 × normalized_lexical
ACRONYM BOOST
Proper initials +0.26

Other initials +0.12; exact token/tag-prefix +0.06. Common terms such as api, db, and os are denied as initials.

TEMPORAL FILTERS
--as-of vs --date

Point-in-time active state versus memories created or updated on one UTC calendar day.

Threshold behavior: supplying --min-similarity requires the vector score to pass; otherwise valid BM25-only matches are excluded. --multi-hop expands only the top three base hits by one graph hop at 0.8× base score.

05

Embeddings and answer engines

Embeddings are lazy and identity-bound. Changing backend/model requires an atomic reindex; answer rerankers sit above hybrid recall.

LayerImplementationsBehavior
EmbeddingsFastEmbed ONNX
Ollama HTTP
Hash 384		BGE-small (384d), MiniLM (384d), Nomic v1.5 (768d), custom ONNX directory, remote/local Ollama, or deterministic offline hash.
Answer rerankerminilm-squad2
tinyroberta-squad2		Local extractive QA; tokenization truncates to 384 tokens, context spans max 20 tokens, SQuAD no-answer gating.
Generative rerankerollama
ollama:<model>		Uses configured Ollama URL/model and grounds responses in selected memories.
Zero-model fallbacktop1Returns the first hybrid result, but abstains when there is no BM25 hit and score is below 0.35.

Lazy initialization and migration

  • LightMem stores its provider in OnceLock; SQL-only commands avoid model initialization.
  • Embedding identity includes card format, FastEmbed version/model, Ollama endpoint/model, or hash version. Custom model identities fingerprint model/tokenizer files.
  • Reindex snapshots records and storage revision, embeds in batches of 32, validates vectors, and swaps the complete index only if revision and cardinality still match.
  • QA engines are process-cached per model directory; ONNX inference is mutex-serialized.
Model operations & switching
$ lmem config --preset local          # Preset 1: 100% offline ONNX embeddings + minilm-squad2 QA
$ lmem config --preset ollama-cloud   # Preset 2: Local ONNX embeddings + Ollama gemma4:31b-cloud reranker
$ lmem config --preset ollama-local   # Preset 3: Local ONNX embeddings + Ollama localhost LLM reranker
$ lmem config --download all          # Pre-cache ONNX models locally for offline operation
$ lmem config --json
config --download all scope: implementation downloads all three embedding presets plus MiniLM SQuAD2. It does not download TinyRoBERTa.

06

Knowledge graph

Graph links are directional rows, while traversal navigates both directions. Explicit links, wikilinks, mentions, shared tags, and semantic similarity can all contribute edges.

EXPLICIT LINKS
source → target

Default relation relates_to; weights clamp to 0.01…10.0; identical edge triples are upserted.

TRAVERSAL
Cycle-safe BFS

Up to 10 hops internally. Score propagates as (previous × weight) / hop; incoming edges receive an “(incoming)” suffix.

WIKILINKS
[[target|label]]

New memories resolve outgoing references and older memories that literally reference the new title.

AUTOLINK
Three discovery signals

Title mentions, two shared non-generic tags, and cosine similarity above the supplied threshold.

Graph operations
$ lmem link "API Gateway" "Auth Service" --relation depends_on --weight 1.5
$ lmem related "API Gateway" --hops 2 --json
$ lmem graph --focus "API Gateway" --hops 2
$ lmem autolink --min-similarity 0.75 --json
MCP import behavior: MCP relations are converted to relationship memory records such as “A connects_to B”; they do not populate memory_links graph edges automatically.
07

Conflicts, supersession, and lifecycle

LightMem combines meaningful-token overlap with vector similarity, then retires superseded records while preserving a newer active identity and carrying over attachments.

01Candidate overlapShared meaningful words and same-category scope for --supersede.
02Similarity gateExact content or max(vector, word_overlap × 0.92).
03Pair selectionBest qualifying older match; vault scan deduplicates pair IDs.
04MergeKeep newer identity; union tags & attachments, max confidence, refresh timestamp.
05RetireRe-embed survivor and soft-expire older record.

Default/Top‑1 conflict merge normally chooses one complete record rather than synthesizing clauses. ONNX has a narrow richer-subset exception. Ollama is the only implementation explicitly prompted to preserve non-conflicting older details.

Lifecycle commands
$ lmem remember "New deployment rule" --supersede
$ lmem conflicts --min-similarity 0.78
$ lmem conflicts --yes -r ollama:qwen2.5:3b
$ lmem deduplicate --json
$ lmem forget <id>          # soft-expire
$ lmem forget <id> --hard   # delete
08

Complete CLI reference

lmem [--connection ID] [--scope user|project|agent] [--session ID] [--global|-g] [--db PATH] [COMMAND]. No command opens the selected vault and renders the Crimson Cloud HUD plus live statistics.

29 commands · aliases included
01 rememberStore text and/or multimodal file attachments+
lmem remember [CONTENT] [-f|--file PATH]... [--extract] [-r MODE] [-t CATEGORY] [--title TITLE] [--tags A,B] [-c FLOAT] [-p|--provenance LEVEL] [--ttl DURATION] [-s|--supersede] [--json]

Stores text, one or more files (-f/--file), or both. When CONTENT is omitted with -f, LightMem auto-generates title and metadata summary from the attached files. --extract explicitly invokes the single configured LLM to describe attached files. Category defaults to inferred (or artifact for file-only memories); JSON returns the created MemoryRecord with attachments.

02 recallHybrid semantic + keyword retrieval & media materialization+
lmem recall QUERY [-t CATEGORY] [--media KIND] [--as-of DATE] [--date DATE] [-l N] [--min-similarity FLOAT] [--precision] [--multi-hop] [-o|--save-to PATH] [-p|--path|--paths] [--json]

Limit defaults to 10. --media image|audio|video|document|any filters by attachment type. --save-to exports verified attachments to disk; --path / --paths (-p) materializes attachments and prints only their absolute file paths (one per line, or JSON array with --json).

03 listChronological, filterable pagination & media listing+
lmem list [-t CATEGORY] [--media KIND] [--status active|expired] [--as-of DATE] [--date DATE] [-l N] [--offset N] [--page N] [-o|--save-to PATH] [-p|--path|--paths] [--json]

Defaults: active, limit 20, offset 0. --page is 1-based and overrides offset. Supports --media filtering, --save-to export, and --path / --paths (-p) raw path output.

04 inspectInspect one or more records, links, and attachments+
lmem inspect TERM... [-o|--save-to PATH] [-p|--path|--paths] [--json] # aliases: get, show

Accepts one or more UUID prefixes or titles. --save-to exports attachments with SHA-256 verification; --path / --paths (-p) prints only materialized file paths (exiting 1 if no attachments exist).

05 deduplicateMerge identical active records+
lmem deduplicate [--json] # alias: dedup

Reconciles tags, title, confidence, and timestamps, then refreshes the indexed survivor. JSON: {"merged":N}.

06 forgetExpire or hard-delete one/all records+
lmem forget [ID] [--all] [--hard] [--json]

Default is soft retirement. --hard permanently deletes the memory and cascades deletion to memory_attachments. --all --hard removes SQLite DB/WAL/SHM files.

07 clearReset the selected vault+
lmem clear [--soft] [--json] # aliases: purge, reset

Hard wipe is the default. --soft expires all active records instead.

08 exportWrite OKF v2, lossless JSON, or .zip transfer bundle+
lmem export [--okf | --json | --bundle] [-o|--output PATH]

OKF is default and active-only. JSON uses a lightmem-backup-v1 envelope. --bundle creates a single-file compressed .zip containing the clean SQLite DB (flushing WAL via VACUUM INTO), all attached physical video, photo, audio, and document files, and a SHA-256 manifest.

08b bundlePortable compressed DB & media transfer bundles (.zip)+
lmem bundle [export|import|info] [OPTIONS]

Packages or restores the complete vault as a single .zip file: clean checkpointed SQLite DB (memories.db), SHA-256 verified manifest (manifest.json), and all raw video, image, audio, and document files (attachments/). Subcommands: export -o <path.zip>, info <file.zip> (inspect without extracting), and import <file.zip> [--replace | --merge].

09 importIngest supported files, directories, or .zip transfer bundles+
lmem import FILE_OR_DIRECTORY [--enrich] [--replace] [--merge] [--json]

Recurses through .md, .okf, .json, and .jsonl while skipping symlinks, hidden files, and index.md. Automatically detects .zip and .lmbundle transfer bundles, restoring the database without re-indexing and materializing all video/photo files into attachments/.

10 answerExtract or synthesize a grounded answer+
lmem answer QUESTION [--precision] [-r MODE] [-t CATEGORY] [--as-of DATE] [--date DATE] [-l N] [--json]

Explicit reranker overrides precision, then configured default applies. JSON returns answer, selected_memory, confidence, and reranker_used; no-evidence is a valid zero-confidence result.

11 configInspect or mutate model configuration+
lmem config [--preset local|ollama-cloud|ollama-local] [--backend onnx|ollama|hash] [--onnx-model SPEC] [--download MODEL] [--url URL] [--model NAME] [--reranker MODE] [--reset-db] [--json] [--yes]

Provides three 1-click setup presets (local, ollama-cloud, ollama-local). Identity-changing embedding configuration requires approved atomic migration on non-empty databases. Supports switching seamlessly between local offline ONNX and Ollama OpenAI-compatible rerankers. Without setters, prints complete formatted configuration tree, available presets, or machine-readable JSON.

12 reindexRebuild the complete vector index+
lmem reindex [--yes]

Prompts on interactive terminals. Non-interactive use requires --yes; diagnostics and progress go to stderr.

13 statsStorage and category telemetry+
lmem stats [--json]

JSON returns total_memories, active_memories, expired_memories, total_vectors, and by_category. Human output also displays selected DB path.

14 conflictsDetect and optionally merge overlaps+
lmem conflicts [-y|--yes|--resolve] [-r MODE] [--min-similarity FLOAT] [--json]

Threshold defaults to 0.78. Interactive choices are yes, next, all, quit. JSON never prompts and only merges when combined with --yes.

15 linkCreate or update a directional edge+
lmem link SOURCE TARGET [-r RELATION] [-w FLOAT] [--json]

Default relation is relates_to and weight 1.0. Self-links fail; existing identical triples update their weight.

16 unlinkRemove one or all edges between nodes+
lmem unlink SOURCE TARGET [-r RELATION] [--json]

Without relation, removes every edge in either direction between the pair. Missing edge returns normally with removed:false.

17 relatedTraverse connected memories+
lmem related ID [-n|--hops N] [--json]

Default 2 hops; implementation clamps to 1…10. JSON records include memory, distance, relation_path, and score.

18 graphRender the full/focused graph+
lmem graph [-f|--focus ID_OR_TITLE] [-n|--hops N] [--json]

No focus returns all active nodes and links. There is no browser option or pagination in this branch.

19 autolinkDiscover edges from content and similarity+
lmem autolink [--min-similarity FLOAT] [--json] # alias: auto-link

Default 0.75, clamped to 0.1…1.0. Returns new_links, total_nodes, and total_edges.

20 connectDeploy the LightMem agent skill+
lmem connect [PLATFORM] [--mcp] [-w|--workspace] [-p|--path PATH] [-l|--list] [--json]

Platforms: antigravity, codex, hermes, cursor, claude, agents, or all. Omitted platform auto-detects; no matches default to antigravity + agents.

21 completionsGenerate shell completion source+
lmem completions bash|zsh|fish|elvish|powershell

Writes the generated completion script to stdout.

22 uninstallRemove binaries and optional data+
lmem uninstall [-a|--purge-data] [-y|--yes]

Removes binaries, completion hooks, and PyPI package attempts. Preserves vault/config/models unless --purge-data.

23 observeExtract and ingest facts from dialogue or transcripts+
lmem observe [TEXT_OR_PATH] [-y|--yes] [--dry-run] [-t CATEGORY] [--tags A,B] [-c FLOAT] [-r MODE] [--json] # alias: ingest

Extracts durable preferences, decisions, and facts from raw text, JSON turn arrays, or files (or stdin when omitted) with provenance observed.

24 identityRegister users, agents, harnesses, and connections+
lmem identity user-add ID [--name NAME] lmem identity agent-add ID --user USER lmem identity harness-add ID [--path PATH] [--name NAME] lmem identity connection-add ID --user USER --agent AGENT --harness HARNESS [--project PROJECT] [--memory-scope user|project|agent] lmem identity list [connections|users|agents|harnesses] [--json] lmem identity show ID [--json]

Creates or inspects local organizational identities. Project scope requires a project; agent scope is separated by user, agent, and optional project. These identities do not provide authentication.

25 contextInspect the active connection and selected vault+
lmem [--connection ID] [--scope SCOPE] context [--json]

Reports the active source identity, scope, and persistent database path. Select a default connection with LIGHTMEM_CONNECTION.

26 setupConfigure local or Ollama models+
lmem setup [--preset local|ollama-local|ollama-cloud] [--url URL] [--model MODEL] [-y|--yes] [--json]

Opens the model setup wizard or applies the selected preset. Model downloads may be required before offline operation.

27 mcpRun the native MCP server over stdio+
lmem [--connection ID] mcp

Starts the stdio JSON-RPC server for an MCP client. The default build enables MCP. Use lmem connect --mcp to configure supported clients automatically.

28 versionDisplay version and build information+
lmem version [--json] lmem --version [--json]

Reports the installed engine version and build metadata.

Python SDK

The lmem distribution has no Python dependencies. It exposes typed dataclasses while delegating execution to the native CLI.

remember()recall()answer()list()get()inspect()bundle_export()bundle_import()bundle_info()observe()forget()deduplicate()conflicts()link()unlink()related()graph()autolink()connect()stats()
Python API
from lmem import LightMem

mem = LightMem(global_db=True)
record = mem.remember(
    "Auth runs on port 8180",
    category="fact",
    title="Auth Port",
    tags=["auth", "docker"],
    files=["./architecture.png"],
)
results = mem.recall("auth port", media="image", limit=5)
paths = mem.inspect(record.id, path=True)
answer = mem.answer("Which port does auth use?")
print(answer.answer, answer.confidence, paths)

# Portable single-file DB & media transfer bundles
bundle_summary = mem.bundle_export("my-vault.zip")
manifest = mem.bundle_info("my-vault.zip")
print(f"Backed up {manifest['record_count']} memories & {manifest['attachment_count']} media files")
mem.bundle_import("my-vault.zip", mode="replace")

Use a registered connection

Python connection context
from lmem import LightMem

# Use a connection registered with the identity commands.
mem = LightMem(connection="codex", session="chat-123")
record = mem.remember("Decision: use SQLite WAL", category="decision")
print(record.context)
print(mem.context())

The SDK also exposes register_user(), register_agent(), register_harness(), register_connection(), identities(), and connection_info().

Native binary resolution

Bundled wheel binary → LMEM_BINARY_PATH / LIGHTMEM_BINARY_PATH → ~/.lightmem/bin → ~/.local/bin → ~/.cargo/bin → PATH → GitHub release auto-download. Candidate files must carry Mach‑O, ELF, or PE signatures; script wrappers are rejected.

Operational model: each SDK method launches lmem --json, parses stdout, and raises RuntimeError for nonzero status or invalid JSON. It is not an in-process Rust extension.

Agent integrations

Connect supported tools through skills or native MCP. Register named connections when you want agents to share project memory while keeping user and agent scopes separate.

Connect with MCP

MCP client setup
$ lmem connect --mcp
$ lmem connect claude --mcp
$ lmem connect cursor --mcp

Automatic MCP configuration supports Claude, Cursor, and Antigravity. A custom MCP client can launch lmem mcp as its stdio server. Skill installation also supports the tools listed below.

Share memory across agents

Example: a shared project vault
$ lmem identity user-add alice --name "Alice"
$ lmem identity agent-add coding --user alice
$ lmem identity connection-add agy --user alice --agent coding --harness antigravity --project myapp --memory-scope project
$ lmem identity connection-add codex --user alice --agent coding --harness codex --project myapp --memory-scope project

$ lmem --connection agy --session chat-123 remember "Decision: use SQLite WAL" -t decision
$ lmem --connection codex recall "database decision"
$ lmem --connection codex context --json

Connections with the same user and project use the same project vault. --scope user|project|agent selects one scope for a command; recall does not combine vaults. Set LIGHTMEM_CONNECTION to choose a default connection. Source metadata records the originating connection and optional session.

Connection selection: Do not combine a connection with --db, LIGHTMEM_DB, or --global. Scopes organize local memory; they are not authentication. Agents must invoke remember or observe to store conversations.

Benchmark harness

Six sequential workloads: ingestion at 100/500/1,000 records, 100-query recall latency/hit rate, temporal snapshots, five-process WAL contention, 1,000-operation RSS tracking, and OKF round trip. It emits BENCHMARK_REPORT.md.

Portability: the benchmark uses Unix ps, hardcodes /tmp/lightmem_bench, and labels the report Apple Silicon. Some PASS/CLEAN labels are constants rather than calculated threshold decisions.

Privacy and operational resilience

The default stack runs locally: SQLite persistence, ONNX embeddings, and ONNX extractive QA. Ollama is optional and may point to local or remote infrastructure.

LOCAL DEFAULT
No required memory cloud

Native SQLite and model cache remain under user-selected local paths.

MIGRATION SAFETY
Atomic vector replacement

Old index remains until a complete revision-consistent replacement is ready.

VALIDATION
Input and vector guards

Blank content, ranges, finite vectors, dimensions, schema versions, and pagination overflow are checked.

CONCURRENCY
WAL + 10s busy timeout

One SQLite connection is shared behind Arc<Mutex<_>>.

Important limits: model downloads are TLS-backed but QA assets are checked only by minimum file size—not checksum/signature. Storage mutex poisoning can panic because repository locks use unwrap(). Row decoding falls back for unknown category/status and malformed timestamps, which can conceal some corruption.

Implementation notes and known mismatches

These are current source-level caveats, not roadmap promises. They are included so agent integrations do not rely on stale README/SKILL behavior.

No Needle integration in this commit

The branch contains ONNX QA, Ollama, and Top‑1 rerankers only. No Needle symbol, dependency, or native C‑FFI loader exists in tracked source.

reranker.rs
recall --precision hardcodes ONNX

It does not honor a configured Ollama or Top‑1 reranker; use answer -r MODE for explicit selection.

import --enrich has no current effect

The flag reaches the importer as an unused parameter.

Graph flags in SKILL.md are stale

graph --browser and --terminal are documented elsewhere but not accepted. Current graph flags are focus, hops, and JSON.

Export destinations require -o/--output

Positional destination examples in older skill text do not match the current Clap interface.

Provenance support in CLI

remember --provenance accepts explicit_statement, validated, observed, corrected, inferred, or imported.

Performance tables disagree

Root README and Python/SKILL documents report materially different reranker latency. Treat those values as environment/cold-start dependent until one benchmark methodology is published.

Python tests gate release builds

Release workflows invoke shared validation, including Python unittest discovery against the compiled native binary.

Manylinux wheel is retagged, not repaired

The Linux wheel is compiled on ubuntu-latest and its tag is rewritten without an auditwheel/manylinux compatibility pass.
